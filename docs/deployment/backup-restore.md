# 备份与恢复

## 备份边界

管理员在“系统管理 / 备份与恢复”中创建完整备份。每个归档只包含：

- `manifest.json`
- `database.dump`
- `uploads/`

归档不包含 `backups/`，也不接受绝对路径、路径遍历或符号链接。应用会保存归档 SHA-256 校验值和元数据；下载、删除与恢复都要求 System Admin 身份。

## 恢复前检查

1. 确认当前 `./data` 有足够空间，并先保留需要回退的归档副本。
2. 在管理页面核对归档文件名、创建时间和校验值。
3. 告知使用者停止业务写入。恢复会覆盖数据库与上传文件，不能撤销。
4. 确认部署日志仅管理员可见。归档、数据库 URL、Cookie 与 Setup Token 都不应写入工单或公开日志。

## 恢复行为

确认恢复后，HuddleTab 进入 Maintenance Mode。活动、消费、结算、附件上传和孤立附件清理会返回 `503 MAINTENANCE_MODE`，直到恢复完成。恢复服务会依次校验归档、恢复数据库与 `uploads/`、执行已提交迁移、进行兼容性与健康检查。失败时维护状态保持开启，避免在半恢复数据上继续写入；部署管理员应检查中文容器日志并从已知完整备份重新恢复。

完整恢复成功后，执行：

```bash
npm run smoke
```

只有 Smoke 通过后才能重新开放业务操作。需要完整演练时，在隔离环境运行：

```bash
npm run verify:backup-restore
```

该脚本会创建测试活动、消费和图片附件，再备份、制造变更、恢复并验证原始记录、附件和健康端点。它需要一个具备 System Admin 权限的测试会话 Cookie，因此只应在隔离环境使用。
